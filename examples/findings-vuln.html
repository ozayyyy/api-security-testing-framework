Business logic: pay a cancelled order

Detector: business_logic | Severity: high | Status: confirmed | Confidence: high

A cancelled order can be paid: cancel returned 200, pay then returned 200 and a re-read shows status=paid. A cancelled order can be paid, so money can be taken for an order the customer cancelled.

Endpoint: /vuln/orders

  • POST http://127.0.0.1:8000/vuln/orders → 200
    {"id": 2, "owner_id": 1, "status": "draft", "price": 100, "quantity": 1, "refunds": 0}
  • POST http://127.0.0.1:8000/vuln/orders/2/cancel → 200
    {"id": 2, "owner_id": 1, "status": "cancelled", "price": 100, "quantity": 1, "refunds": 0}
  • POST http://127.0.0.1:8000/vuln/orders/2/pay → 200
    {"id": 2, "owner_id": 1, "status": "paid", "price": 100, "quantity": 1, "refunds": 0}
  • GET http://127.0.0.1:8000/vuln/orders/2 → 200
    {"id": 2, "owner_id": 1, "status": "paid", "price": 100, "quantity": 1, "refunds": 0}

Business logic: refund the same order twice

Detector: business_logic | Severity: high | Status: confirmed | Confidence: high

The same order refunded twice: both refund calls returned 200 and a re-read shows refunds=2. The same order can be refunded twice, so the seller pays out twice for one purchase.

Endpoint: /vuln/orders

  • POST http://127.0.0.1:8000/vuln/orders → 200

  • POST http://127.0.0.1:8000/vuln/orders/3/pay → 200

    {"id": 3, "owner_id": 1, "status": "refunded", "price": 100, "quantity": 1, "refunds": 1}
  • POST http://127.0.0.1:8000/vuln/orders/3/refund → 200
    {"id": 3, "owner_id": 1, "status": "refunded", "price": 100, "quantity": 1, "refunds": 2}
  • GET http://127.0.0.1:8000/vuln/orders/3 → 200
    {"id": 3, "owner_id": 1, "status": "refunded", "price": 100, "quantity": 1, "refunds": 2}
